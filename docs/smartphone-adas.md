# スマホによる運転支援：歩行者・二輪車の注意喚起

事故を減らすため、追加センサーや車両への接続を必要としない注意喚起を段階的に追加する。
本変更は **実験機能**。自動ブレーキ・操舵は行わず、事故ゼロや検出精度を保証しない。

## 使い方

1. 停車中にスマホを固定し、背面カメラを道路の前方へ向ける。
2. ドラレコ画面で「歩行者・二輪車の注意喚起（実験機能）」を有効にする。既定はオフ。設定は端末に保存する。
3. 録画を開始する。対象が前方中央に継続して見える場合、音・振動・音声・画面の帯で注意を促す。
4. 設定変更は録画を止めてから行う。カメラを運転者に向ける居眠り検知と、前方を撮影するドラレコは同時利用しない。

物体検出と判定には既存の同梱モデルを使い、通信・追加モデルダウンロード・新しい権限は不要。
音声の利用可否は端末にインストールされた TTS エンジンと言語データによる。音と振動は既存の警告経路を使う。
ドラレコ動画は従来通り端末に保存する。別機能の OSM 制限速度・オービス情報取得には通信が必要。

## 判定と限界

- 対象は COCO の person / bicycle / motorcycle。車線、横断歩道、右側・左側通行の地図情報には依存しない。
- 正立画像全体の座標で中心 x が 0.35〜0.65、下端 y が 0.6 以上、高さが 0.18 以上、信頼度が 0.6 以上の対象を候補にする。
- 同じ種類で枠の IoU が 0.2 を超える対象を追跡し、3 観測以上かつ 500ms 以上継続してから通知する。サイズは距離の測定ではない。
- 対象消失・切り替わり・750ms を超える観測間隔では確認履歴を捨てる。通知間隔は最低 8 秒。
- 有効な速度が 5km/h 未満、無効な速度値、旋回中は通知しない。速度不明の場合は存在の注意喚起を続けるため、停車中に通知する場合がある。
- 本機能オンでは中央拡大を全画面推論へ切り替える。推論回数は増やさないが、遠方の車は小さく写り、既存の前方衝突警報の検出距離が短くなる可能性がある。
- 中央の範囲は進路の近似にすぎない。歩道上の人の誤報、画面端からの急な飛び出し、夜・雨・逆光・遮蔽・小さい対象の見逃しがある。将来の交差や衝突時刻は予測しない。
- 同一フレームで複数の知らせが出た場合、前方衝突、歩行者・二輪車、車間距離、発進、車線逸脱の順で一つを読み上げる。

## 検証

```bash
flutter gen-l10n
flutter analyze
flutter test
# 検出結果は全画面の正立座標で用意する（中央クロップ済み映像の評価では不十分）
dart run tool/replay_road.dart detections.jsonl 40 --road-users --trace
```

`test/road_user_test.dart` は候補種別、時間確認、誤報抑制、履歴破棄、設定保存、日英文言を検証する。
これらは判定のテストであり、実際の検出精度や事故低減の証明ではない。

公開前には release ビルドの実機起動に加え、閉鎖コース・収録映像で昼夜、雨、混雑した道路、複数の歩行者、自転車、二輪車、低価格端末を評価する。
対象別の見逃し率・一時間あたり誤報・検知から通知までの遅延・FPS・発熱・バッテリー消費を記録する。
走行中の設定操作や、警報を頼りにした公道試験は行わない。

## 次の段階

- 対象地域の収録映像による精度・誤報評価と閾値の調整。
- 二輪車、三輪タクシー、動物など、既存モデルで不足する対象のデータ整備。
- カメラ遮蔽・暗所・推論停止を利用者に伝える可用性表示。
- 実測に基づく低価格端末の省電力モードと、対象地域の言語対応。

参考：モデルの構成は [TensorFlow の公式物体検出サンプル](https://github.com/tensorflow/examples/blob/master/lite/examples/object_detection/android/README.md) に対応する。モデルが対応するクラスと、道路上で十分に検知できるかは別途検証が必要。
