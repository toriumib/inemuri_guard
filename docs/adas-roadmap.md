# 総合 ADAS（無料）への道筋 — 2026-09-23

居眠りガードを「車・歩行の両方で使う無料の運転支援」へ広げる。
きっかけ: 後ろの車の運転者がスマホを落として拾い、追突された経験。
**見張るのは「居眠り・スマホ操作・前方不注意」の3つ**。

## いちばん大きな制約: カメラは同時に 1 つ

多くの Android 端末は前面と背面を同時に開けない（Concurrent Camera API に対応する端末は一部）。
だから「運転者を見る（前面）」と「道路を見る（背面：ドラレコ・前方衝突警報・車線逸脱）」は**排他のモード**になる。
モードを選ばせ、同時に使えると嘘をつかない。

## 入ったもの（v2.0 候補・実機未検証）

| 機能 | 中身 | 根拠・注意 |
|---|---|---|
| 手元見（スマホ操作）の注意 | 車モードで、普段より 22° 以上うつむいた状態が 2 秒続いたら短く知らせる（脇見と同じ扱い） | 100-Car 研究（Klauer ら 2006）: 前方から 2 秒超目を離すと事故・ニアミスの危険がおよそ倍。脇見も 3→2 秒に |
| 夜道ライト | 外側ライトを 2Hz（200ms 点・300ms 消）で点滅 | 反射材は車のライトが当たらないと光らない。自分で光れば横・斜めからも見える。画面オフで続くかは実機未検証 |
| ドラレコ（試験的） | 背面カメラで 1 分ごと、新しい 10 本を残して上書き。2.5G 以上の衝撃か「保護」で前後 2 本を保護。音なし・端末内のみ | 画面を開いている間だけ（camera プラグインが Activity に縛られる）。区切りで 1 秒弱の抜け。衝撃のしきい値は実車未測定 |

## 次にやる候補

1. **前方衝突警報（FCW）** — ドラレコ画面で背面カメラを使っている間に、前の車の箱の大きさの変化から TTC（衝突までの秒数）を出す。
   物体検出は ML Kit Object Detection（端末内・無料）か YOLOX / RT-DETR（Apache-2.0）を TFLite で。追跡は ByteTrack（MIT）。
2. **前の車の発進お知らせ** — 信号待ちで前の車が動いたのに止まったまま（＝手元を見ている）を知らせる。FCW と同じ検出で作れる。
3. **後ろからの追突に備える** — 停車中に後方を映して、近づく速さが落ちない車を検知。車内の置き場所が難しいので後回し。
4. **歩行者の接近車スキャン** — かざしたときに近づく車の TTC で振動。「かざし続ける」こと自体が危ないので、止まったときだけ動く設計にする。
5. **背面でもドラレコ** — EyeService と同じく native Camera2 を Service で持つ。
6. **速度の知らせ** — GPS の速度と、本人が決めた上限で知らせる（通信なし）。道路ごとの制限速度は OpenStreetMap（Overpass API、ODbL・要クレジット）で取れるが、**位置が外部サーバーへ出る**ので「外に何も送らない」という約束とぶつかる。入れるなら既定 OFF・明示の同意・プライバシーポリシー改訂とセット。本人の判断待ち。

## やらない／できないもの

- **取り締まり情報**: 公開 API がない。Waze の警察報告は提携（Waze for Cities）向けで、スクレイピングは規約違反。
  都道府県警の「速度取締り予定」は県ごとに PDF・HTML でばらばら、多くは路線名だけ。固定オービスの位置を網羅した公的なオープンデータも無い（民間のまとめは著作物）。
- **カーロケ受信**: レーダー探知機は専用の受信回路で警察無線の電波を拾う。スマホにはその帯域の受信機が無いので原理的に不可。
  加えて、他人あての無線の内容を利用することは電波法 59 条（秘密の保護）に触れうる。
- 代わりに**制限速度そのものを知らせる**（上の 6）ほうが、事故を減らす目的にも合う。

## 免責

ドラレコ・カーナビと同じ水準の免責（2026-09-11 の方針）を、新機能にも当てる。
「事故を防ぐ」「保証する」とは書かない。補助の道具であること、運転中に操作しないこと。
