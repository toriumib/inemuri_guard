# スマホ 1 台でどの車にも・歩く人にも ADAS を — オープンソース計画（2026-09-23）

> 高級車でなくても、スマホ（と、あれば AI グラス）で最新の ADAS に近いものを。
> 無料・オープンソース（Apache-2.0）。居眠りガードをこの計画の出発点にする。
> 現状の実装と制約は [adas-roadmap.md](adas-roadmap.md)。

## 1. 類似のもの（2026-09 時点で調べた範囲）

| 名前 | 何をするか | 足りないところ |
|---|---|---|
| **openpilot**（comma.ai、OSS） | 車線中央維持・ACC を 300 車種以上で置き換える | 専用機（comma）と車種別ハーネスが要る。対応車種だけ。運転者監視はあるが歩行者側は無い |
| AONE Safe Driving（Android） | 車線逸脱・前方衝突警報 | 前方だけ。運転者の居眠り・スマホ操作は見ない。OSS ではない |
| AutoBoy Dash Cam / DailyRoads Voyager | ドラレコ＋簡易 LDW/FCW | 同上 |
| Nexar | ドラレコ（専用機＋アプリ）、衝突検知と通報、クラウド保存 | 専用機前提。映像をクラウドへ上げる設計 |
| ナビタイム ドライブサポーター | カーナビ、渋滞、**オービス・取締情報** | カメラの ADAS ではない。取締情報は自社データ（公開 API ではない） |
| CarSafe / DriveSafe（Dartmouth ほかの研究） | 前後カメラ＋センサーで居眠り・脇見・危険運転を検知 | 研究止まり。製品として残っていない |
| **WalkSafe**（Dartmouth、2012 年の研究） | 歩きスマホ中、背面カメラで近づく車を検知し振動 | 研究止まり。通話中だけ動く設計 |
| Oko（AYES、iOS） | 視覚障害者向けに歩行者信号を読む | 車の接近は見ない |
| Meta のメガネ（Ray-Ban Meta / Display） | Device Access Toolkit でカメラ映像と音声を自分のアプリへ流せる。Display はメガネに表示もできる | 開発者プレビュー。一般公開できるのは一部の提携先だけ（一般公開は 2026 年の予定と発表） |

**空いている場所**: 「運転者を見る（居眠り・スマホ・脇見）」「前を見る（衝突・発進・車線）」「歩く人を守る」を
**1 つの無料 OSS アプリ**でやっているものは見当たらない。openpilot は強いが車と専用機を選ぶ。スマホアプリは
ドラレコ系か運転者監視系のどちらかだけで、歩行者側は研究で止まっている。

## 2. 何を作るか

**「スマホ 1 台で、どの車にも、歩く人にも」**。車に付け足すのではなく、人が持っている物だけで動かす。

### モード（カメラは同時に 1 つが基本なので、モードで分ける）

| モード | 使うもの | 機能 |
|---|---|---|
| 運転者 | 前面カメラ | 居眠り（済）・スマホ操作＝手元見（済）・脇見（済）・制限速度（済） |
| 前方 | 背面カメラ | ドラレコ（済・試験的）、**前方衝突警報（FCW）**、**前の車の発進お知らせ**、車線逸脱（LDW）、歩行者・自転車の飛び出し |
| 両方 | 前後カメラ同時 | 上の 2 つを同時に。**同時に開ける端末だけ**（Android 11 以降の `getConcurrentCameraIds()` で端末に聞く。空なら出さない） |
| 停車中の後方 | 背面カメラを後ろへ | 信号待ちで、減速しない後続車を検知してハザードを促す（追突された経験への直接の答え）。置き場所が課題 |
| 歩行 | スマホ背面カメラ（後ろ向き）＋ AI グラス（前） | 近づく車の TTC で振動・音、夜道ライト（済）、歩きスマホの注意、横断時の左右確認 |

### AI グラスの役割（歩行モード）

- **グラスは「前」、スマホは「後ろ」**。グラスのカメラは顔の向きを見るので、背後から来る車は映らない。
  スマホをバッグや胸に後ろ向きで付けて背後を見る。役割を分ければ、どちらも「かざす」必要がない
- グラスの映像はスマホへ流し、**推論はスマホでやる**（Meta の Toolkit もその形）。遅延と解像度は実測するまで約束しない
- 知らせは**音と振動が主**。表示のあるグラスでも、出すのは矢印 1 つ程度にする。視界を塞ぐ表示は危険を増やす
- **運転中はグラスの表示を使わない**。道路交通法 71 条 5 号の 5 は、運転中に画像表示用装置を注視することを禁じている。運転中は音だけ

### その他のセンサー

- **IMU（加速度・ジャイロ）**: 衝突検知（済）、急ブレーキ・急ハンドル、歩いているか止まっているかの判定（歩行モードの自動起動）
- **GPS**: 速度、制限速度（済）
- **マイク**: 寝息（済・BETA）、緊急車両のサイレン検知（候補。端末内の音響分類、YAMNet は Apache-2.0）
- **OBD-II（任意）**: 1,000〜2,000 円の BLE アダプタ（ELM327 系）があれば、車速・ブレーキ・ウインカーが取れる。
  ウインカーを出していれば車線逸脱を鳴らさない、ができる。無くても動く設計を崩さない
- **スマートウォッチ**: 手首の振動（通知の転送は済）

## 3. 中身（全部オープンソース・全部端末内で推論）

| 役割 | 候補 | ライセンス | 注意 |
|---|---|---|---|
| 顔・目・頭の向き | ML Kit Face（Android、済）/ MediaPipe Face Landmarker（Web、済） | 無料 / Apache-2.0 | |
| 車・歩行者・自転車の検出 | **YOLOX**、**RT-DETR**、ML Kit Object Detection | Apache-2.0 | **Ultralytics YOLOv8/11 は AGPL-3.0** なので使わない（アプリ全体に波及する） |
| 追跡 | **ByteTrack** | MIT | DeepSORT 系は実装によって GPL があるので避ける |
| 距離・接近 | 箱の大きさの変化から TTC（深度推定なしで出せる） | — | まずはこれで十分。深度推定は後回し |
| 深度（必要になったら） | Depth Anything V2 **Small** | Apache-2.0 | **Base/Large は CC-BY-NC（商用不可）**。Small 以外を入れない |
| 車線 | Ultra-Fast-Lane-Detection 系 | MIT | 日本の道路で実測が要る |
| 交通信号・標識 | 検出器を日本の信号・標識で追加学習 | — | 学習データのライセンスを先に確認 |
| 音 | YAMNet | Apache-2.0 | サイレン・クラクション |
| 地図 | OpenStreetMap（Overpass） | ODbL | クレジット表示（済） |

**判定と出力は今の `AlertCoordinator` に寄せる**。知らせの優先順位（衝突 > 居眠り > スマホ操作 > 速度）を
1 か所で決める。複数が同時に鳴ると、どれにも反応できなくなる。

## 4. 進め方と「できた」の基準

| 段階 | 中身 | できたと言える条件 |
|---|---|---|
| 0（済） | 居眠り・手元見・脇見・制限速度・ドラレコ・夜道ライト | テスト 127 件。**実機での検証はまだ** |
| 1 | 実機検証、OSS として公開 | 実車 3 回・夜道 1 回の記録を docs/ に残す。公開前にコミット履歴の著者メールを書き換える（本人作業） |
| 2 | 前方モード: FCW＋発進お知らせ | 録画した走行動画で、前の車への TTC 警告の見逃しと誤報の数を出す（見逃し率・1 時間あたりの誤報） |
| 3 | 同時カメラ対応端末で「両方」モード | 対応端末の一覧を実測で作る。非対応端末では出さない |
| 4 | 歩行モード: スマホ後ろ向きで接近車の TTC | 歩道で後方 30m の車に 2 秒前までに知らせる。電池 1 時間あたりの消費を測る |
| 5 | AI グラス（Meta Toolkit の一般公開後） | 映像の遅延を実測し、TTC の計算に入れる。遅延が 300ms を超えるなら前方の危険予告は出さない |
| 6 | OBD-II・サイレン・停車中の後方 | 任意機能として |

## 5. オープンソースにするときに決めておくこと

- **ライセンス**: Apache-2.0（済）。**依存とモデルに AGPL・非商用が紛れ込まないよう CI でライセンスを検査**する
- **データを集めない**: 走行映像を学習用に集めない。集めると「映像は端末の外に出ない」が崩れ、個人情報（ナンバー・顔）の管理が要る。
  精度の評価は、ライセンスが明確な公開データセットと、本人の実車データ（本人の端末内）でやる
- **名前**: 機能が「居眠り」を超えた。アプリ名とパッケージ名（Play 上は変えられない）を分けて考える
- **安全の言い方**: 「事故を防ぐ」「自動ブレーキ」とは言わない。**知らせるだけ**で、車は操作しない（openpilot と違い、車の制御には触れない）。
  これにより車両側の型式・保安基準の話にならない

## 6. 危ないところ

- **誤報で慣れる**: 誤報が多いと、本物の警告も無視されるようになる。誤報の数を段階 2 の合格条件に入れているのはこのため
- **熱**: ダッシュボードのスマホは直射日光で熱くなり、カメラと推論が止まる。温度を見て、止めたら画面と音で伝える（「黙って止まらない」はこのアプリの背骨）
- **電池**: 2 つのカメラ＋推論は重い。車は給電が前提、歩行モードは 1 時間あたりの消費を測って書く
- **固定**: 走行中にスマホが落ちること自体が、この計画のきっかけになった事故と同じ種類の危険。固定のしかたを最初の画面で案内する
