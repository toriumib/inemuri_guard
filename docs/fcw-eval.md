# 前方衝突警報（FCW）の測り方と、いまの実力（2026-09-24）

「誤報を減らして実用にする」には、見逃しと誤報を**数で**言えないといけない。
アプリの判定（`DriveJudge`）をそのまま PC で再生できるようにしてある。

## 手順（自分のドラレコ映像で）

1. アプリのドラレコで走る（前方モード）。映像は端末の `…/app_flutter/dashcam/loop/` と `locked/`
2. PC に取り出す（例: `adb pull /sdcard/Android/data/com.toriumi.inemuri_guard/files/...`、または「共有・保存」）
3. アプリと同じモデル・同じ切り出しで検出する

   ```bash
   python tools/road_eval/detect_video.py drive.mp4 out.jsonl lite2 center
   ```
   遅い端末（SSD になる端末）の再現なら `ssd center`。

4. アプリと同じ判定で再生する（速度は一定値を渡す）

   ```bash
   dart run tool/replay_road.dart out.jsonl 40 --trace
   ```
   出た知らせの時刻を映像で見返し、本当に危なかったか（正報）か、そうでないか（誤報）を人が数える。
   **合格の目安**: 誤報 1 時間あたり 1 回以下、正報を逃さない。

映像はこの PC の中だけで処理し、どこにも送らない。ナンバーや人が映るので公開しない。

## いまの実力（合成映像。実写の走行ではない）

止まっているバス（実写の写真）に 36km/h（10m/s）で 40m 先から近づく 4 秒の映像を合成して測った
（`tools/road_eval/` のスクリプトで再現できる。写真はリポジトリに入れていない）。

| モデル | 見る範囲 | 初めて見つけた距離 | 警報 | そのときの本当の TTC |
|---|---|---|---|---|
| SSD MobileNet v1 | 画面全体 | 約 5m | 鳴らない | — |
| SSD MobileNet v1 | 中央の切り出し | 約 19m | 3.2 秒 | 0.8 秒 |
| EfficientDet-Lite2 | 中央の切り出し | 約 35m | 2.7 秒 | 1.3 秒 |

- **TTC の計算そのものは正確**（2.67 秒で本当 1.33 秒に対し推定 1.43 秒、2.93 秒で 1.07 秒に対し 1.12 秒）。
  遅れの原因は計算ではなく、**遠い車を安定して見つけられないこと**
- 見つけられる距離（`range_test.py`、スコア 0.45 前後で見つかる画面幅）:
  SSD 全体 30%（約 4m）→ SSD 中央 10%（約 13m）→ Lite2 中央 8%（約 17m）
- Lite2 は PC で 1 フレーム 119ms（SSD は 25ms）。アプリは起動時に 3 回試し、1 回 300ms 以内の端末だけ Lite2 を使う
- **目標（TTC 2.0 秒で知らせる）にはまだ届いていない**。36km/h で 20m 先の車を安定して見つける必要がある

## この日に直したこと（誤報と遅れの両方）

| 直したこと | 理由 |
|---|---|
| 前の車を重なり（IoU）で追い続ける | 隣の車線の車に乗り移ると幅が急に変わって見える（誤報） |
| 幅の対数に直線を当てはめ、窓の真ん中→今に補正 | 見かけの幅は距離に反比例するので ln(幅) の傾き＝1/TTC。2 点の差だと揺れで跳ねる |
| 見失っても 0.5 秒は同じ車とみなす | 遠い車は 1 回おきにしか見つからない。そのたび履歴を捨てると TTC が出ない |
| 幅の急増で捨てるのは 8 割から | 衝突直前は本当に 4〜5 割ずつ大きくなる |
| 曲がっている間（角速度 20°/s 超）は見ない | 枠が横に流れて幅が乱れる（誤報） |
| 画面中央だけを見る | 同じモデルで見つけられる距離が 3 倍 |
